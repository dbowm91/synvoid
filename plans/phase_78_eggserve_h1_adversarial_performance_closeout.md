# Phase 78 Plan: EggServe H1 Adversarial, Performance, and Closeout Qualification

Status: planned; blocked on Phase 77 closure and hosted CI.

Registered in: `plans/roadmap.md`.

Parent campaign:
`plans/eggserve_0_3_h1_requalification_and_adoption_roadmap.md`.

## Purpose

Prove that the completed plaintext/TLS-H1 runtime consolidation preserves
SynVoid's correctness, security, configuration, WebSocket, shutdown, and
performance contracts; remove only genuinely superseded Hyper-H1 machinery;
and close the program as ADOPTED or roll back to the last qualified Hyper
state.

This phase owns final evidence and deletion authority.

## Track A — immutable comparison baselines

Record:

- pre-adoption baseline: the exact SHA immediately before Phase 76 production
  switch;
- candidate: exact Phase 77 convergence SHA;
- compiler/profile/host;
- EggServe versions/checksums;
- dependency graphs.

Do not compare against the old Phase 65/72 heads for performance conclusions;
they remain architecture/history evidence only.

## Track B — adversarial H1 parser/framing matrix

Run both plaintext and real TLS-H1 against:

- partial/slow request lines;
- partial/slow headers;
- header-count boundary;
- parser-buffer boundary;
- aggregate header-byte boundary;
- duplicate Content-Length;
- conflicting Content-Length;
- TE/CL corpus matching current Hyper-normalization truth;
- invalid Host/authority;
- unusual legal header bytes;
- oversized body;
- chunked body;
- trailers;
- early EOF;
- pipelined/keep-alive sequences;
- malformed upgrade attempts;
- protocol sniff failures on plaintext.

Compare against the pre-adoption baseline where wire behavior is part of the
contract.

No test may weaken a fail-closed behavior merely to match EggServe defaults.

## Track C — full valid-config boundary matrix

Exercise values at important validation edges, especially those that blocked
the initial 0.3.0 requalification:

- parser buffer > 4 MiB if still valid in SynVoid;
- headers > 10,000 if still valid;
- ingress aggregate header ceiling > 1 MiB if still valid;
- low ingress header ceilings;
- max streaming body boundaries;
- deprecated compatibility keys;
- max request admission.

The adopted runtime must honor the final Phase 73 compatibility decision. If a
valid config cannot start or behaves more narrowly than documented, adoption
fails unless a separately approved compatibility plan changed that contract.

## Track D — per-site response metadata matrix

On one process/runtime host at least two sites with different settings and
prove:

- Date enabled vs disabled;
- different Date jitter;
- different Server token;
- no Server token;
- security header differences;
- Set-Cookie duplicates;
- Alt-Svc;
- streaming/static/upstream responses;
- errors generated by SynVoid;
- errors generated by EggServe pre-service runtime.

Confirm EggServe final framing does not erase the per-site policy contract.

## Track E — WebSocket/tunnel adversarial matrix

Plaintext and TLS:

- ordinary upgrade;
- app-server upgrade;
- invalid/missing key;
- protocol negotiation;
- immediate post-upgrade bytes;
- large message boundary;
- WAF block;
- peer half-close/reset;
- upstream failure;
- shutdown while active;
- multiple simultaneous tunnels;
- external EggServe tunnel admission remains non-authoritative.

Verify no tunnel task survives owning connection/runtime shutdown.

## Track F — body/stream/backpressure resource matrix

Cover:

- small buffered request;
- large streamed request;
- chunk WAF;
- tarpit response;
- upstream streaming response;
- slow client upload;
- slow client response reader;
- client disconnect mid-request;
- client disconnect mid-response;
- trailer-producing response;
- repeated keep-alive requests.

Measure bounded memory/RSS where practical and task/permit cleanup.

No forced buffering is allowed.

## Track G — same-host performance comparison

Use the repository's established HTTP benchmark method or add a narrow
reproducible harness if the old one is unsuitable.

At minimum compare pre-adoption vs candidate for:

- small keep-alive request throughput;
- p50/p95/p99 latency;
- concurrent small requests;
- representative streamed response;
- representative request body;
- established TLS-H1;
- TLS handshake churn only as context (TLS stack is unchanged);
- WebSocket echo/tunnel if a stable harness exists;
- RSS/resource count.

Record raw trial evidence and environment.

Decision rules:

- do not claim improvement from package count alone;
- investigate any material tail/throughput regression;
- accept only explicitly documented tradeoffs that do not undermine the
  consolidation goal;
- if EggServe materially regresses the common H1 path with no offsetting
  maintenance/security value, rollback is valid.

## Track H — dependency/footprint adjudication

Record final:

```bash
cargo tree -i hyper
cargo tree -i hyper-util
cargo tree -i eggserve-server
cargo tree -i eggserve-primitives
cargo tree -d
```

State truthfully:

- Hyper remains because H2 and other consumers require it, if so;
- which H1-specific modules/dependencies disappeared;
- direct EggServe graph delta;
- binary-size change under the same profile.

Do not claim "Hyper removed" unless it truly leaves the graph.

## Track I — remove superseded production H1 machinery

Only after all prior tracks pass:

- remove production plaintext/TLS H1 builder construction;
- remove `src/http/h1_policy.rs` if no longer used by production/tests;
- remove test-only legacy Hyper differential lane after final A/B evidence is
  captured;
- simplify connection wrapper types that existed only to hold
  `TokioIo<...>` for Hyper H1;
- remove stale comments/imports/guards;
- retain H2 Hyper code and tests;
- retain Phase 70–72 evidence as historical.

No broad HTTP cleanup beyond now-dead H1 machinery.

## Track K — rollback criterion

Before deleting the legacy test lane, ensure the Phase 76 pre-adoption SHA is a
clean rollback point.

Close `RETAINED_ROLLBACK` and restore the qualified Hyper production path if
any unresolved issue remains in:

- valid config support;
- per-site response metadata;
- parser/framing security;
- WebSocket;
- shutdown/task ownership;
- body streaming/WAF;
- unacceptable performance/resource regression.

Do not ship a partial production split where plaintext uses EggServe and
TLS-H1 reverts to Hyper unless a separate explicit architecture plan approves
that long-term split.

## Acceptance criteria

- [ ] adversarial plaintext and TLS-H1 matrix passes.
- [ ] full valid-config space remains supported according to final docs.
- [ ] per-site Date/Server/security policy is preserved.
- [ ] body streaming/trailers/backpressure/WAF behavior is preserved.
- [ ] WebSocket/app-server tunnel matrix passes.
- [ ] shutdown leaves no owned tunnel/request tasks.
- [ ] same-host performance/resource comparison is retained.
- [ ] dependency/binary-size delta is measured.
- [ ] superseded H1-only production machinery is removed only after proof.
- [ ] H2/H3 remain unchanged.
- [ ] final architecture closeout exists.
- [ ] roadmap/status/evidence are reconciled.
- [ ] final proof-bearing SHA has green hosted CI.
- [ ] terminal result is explicitly ADOPTED or RETAINED_ROLLBACK.

## Non-goals

- No H2/H3 transport migration.
- No new HTTP features.
- No config redesign beyond previously approved compatibility work.
- No unrelated root-module cleanup.
